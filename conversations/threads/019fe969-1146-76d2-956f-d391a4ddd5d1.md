你现在已经能通过 `docker exec` 进入容器了。配置“Mac 免密登录容器”，本质上是：

Mac 生成 SSH 密钥 → 公钥放进容器 → 容器启动 `sshd`。

由于容器使用了 `--network=host`，它和宿主机共用端口，所以不要使用默认的 22 端口，建议给容器 SSH 使用 `2222`。

### 1. 在 Mac 上生成密钥

Mac 终端执行：

```bash
ls ~/.ssh/id_ed25519.pub
```

如果不存在，就生成：

```bash
ssh-keygen -t ed25519 -C "yanghaoxiang-mac"
```

一路回车即可。然后复制公钥：

```bash
pbcopy < ~/.ssh/id_ed25519.pub
```

### 2. 在容器中安装 SSH 服务

进入容器：

```bash
sudo docker exec -it yanghaoxiang_sglang_0.5.16_preview /bin/bash
```

先判断系统类型：

```bash
cat /etc/os-release
```

Ubuntu/Debian：

```bash
apt-get update
apt-get install -y openssh-server
```

CentOS/RHEL/Rocky：

```bash
yum install -y openssh-server
```

生成服务端密钥：

```bash
ssh-keygen -A
mkdir -p /run/sshd
```

### 3. 将 Mac 公钥放进容器

如果准备使用 `root` 登录容器：

```bash
mkdir -p /root/.ssh
chmod 700 /root/.ssh
touch /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
```

然后执行：

```bash
vi /root/.ssh/authorized_keys
```

把刚才 Mac 复制的、以 `ssh-ed25519` 开头的整行公钥粘贴进去并保存。

也可以直接用下面的方式粘贴：

```bash
cat >> /root/.ssh/authorized_keys
```

粘贴公钥后按回车，再按 `Ctrl+D`。

### 4. 配置容器 SSH 端口

编辑：

```bash
vi /etc/ssh/sshd_config
```

确认或添加：

```text
Port 2222
PubkeyAuthentication yes
PermitRootLogin prohibit-password
PasswordAuthentication no
```

检查配置并启动：

```bash
/usr/sbin/sshd -t
/usr/sbin/sshd
```

确认监听：

```bash
ss -lntp | grep 2222
```

### 5. 从 Mac 登录

如果宿主机的 IP 是 `HOST_IP`：

```bash
ssh -p 2222 root@HOST_IP
```

第一次会提示确认指纹，输入：

```text
yes
```

之后应该可以免密登录。

如果公司网络没有开放宿主机的 `2222` 端口，可以通过宿主机转发。Mac 第一个终端执行：

```bash
ssh -L 12222:127.0.0.1:2222 yanghaoxiang_i@HOST_IP
```

保持这个连接不要关闭，然后 Mac 第二个终端执行：

```bash
ssh -p 12222 root@127.0.0.1
```

补充一点：`--network=host` 下，`docker run -p 2222:22` 不会起到常规端口映射作用，所以这里必须直接让容器中的 `sshd` 监听宿主机尚未占用的 `2222` 端口。容器被删除重建后，SSH 配置也会丢失；长期使用建议把 `/root/.ssh` 和 SSH 配置挂载到持久化目录。

先在 Mac 的 `~/.ssh/config` 中，给你实际登录的服务器配置增加：

```sshconfig
Host ml-pro5000-ser169
    HostName 服务器IP
    User yanghaoxiang_i
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
    ExitOnForwardFailure yes
    RemoteForward 127.0.0.1:17897 127.0.0.1:7897
```

如果你原本已经有 `Host ml-pro5000-ser169`，只需要在原配置中增加最后一行。

然后在 Mac 上确认代理确实监听 `7897`：

```bash
lsof -nP -iTCP:7897 -sTCP:LISTEN
```

重新建立 SSH 连接：

```bash
ssh ml-pro5000-ser169
```

也可以专门开一个终端保持隧道：

```bash
ssh -NT ml-pro5000-ser169
```

出现下面这类错误，说明远端 `17897` 已经被占用：

```text
remote port forwarding failed for listen port 17897
```

可以换一个端口，例如 `17898`。

进入容器后设置代理：

```bash
export http_proxy=http://127.0.0.1:17897
export https_proxy=http://127.0.0.1:17897
export HTTP_PROXY=http://127.0.0.1:17897
export HTTPS_PROXY=http://127.0.0.1:17897
export no_proxy=localhost,127.0.0.1
export NO_PROXY=localhost,127.0.0.1
```

测试代理：

```bash
curl -I -x http://127.0.0.1:17897 https://archive.ubuntu.com
```

测试成功后安装：

```bash
apt-get update
apt-get install -y openssh-server
```

也可以只让本次 `apt` 使用代理，不设置环境变量：

```bash
apt-get \
  -o Acquire::http::Proxy="http://127.0.0.1:17897" \
  -o Acquire::https::Proxy="http://127.0.0.1:17897" \
  update
```

```bash
apt-get \
  -o Acquire::http::Proxy="http://127.0.0.1:17897" \
  -o Acquire::https::Proxy="http://127.0.0.1:17897" \
  install -y openssh-server
```

如果 Mac 上的 `7897` 是 Clash/Surge 的 HTTP 或 mixed 端口，上述配置可以直接使用；如果它是纯 SOCKS5 端口，则代理地址需要改为：

```bash
export http_proxy=socks5h://127.0.0.1:17897
export https_proxy=socks5h://127.0.0.1:17897
```

但对于 `apt`，优先使用 Clash 的 HTTP/mixed 端口更稳。SSH 隧道所在的 Mac 终端不能关闭，否则容器的代理会立即失效。

如果 `~C` 提示 command line disabled，就只能重新通过原来那个可用的登录方式连接，并在登录命令中增加：

```bash
-R 127.0.0.1:17897:127.0.0.1:7897
```

例如：

```bash
ssh -R 127.0.0.1:17897:127.0.0.1:7897 原来能成功登录的SSH别名
```

关键是使用“原来成功进入当前宿主机”的完整 SSH 路径；直接访问 `10.207.192.208:22` 当前不可达。
