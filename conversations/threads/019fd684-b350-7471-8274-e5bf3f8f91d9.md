### 107. assistant · 2026-08-10T07:47:28.396Z

来源: `rollout-2026-08-06T10-00-48-019fd684-b350-7471-8274-e5bf3f8f91d9.jsonl:1062`

这个 PR 的核心作用是：让 SGLang 的“PD 分离部署 + DSpark 投机解码”支持 Pipeline Parallelism（PP）。

目前社区代码中，PD + DSpark 在不开 PP 时可以工作；开启 PP 后，DSpark 所需的目标层 hidden states 分散在不同 PP stage，无法直接完成 context projection 和 draft KV 构建。这个 PR 就是在解决该问题。

主要改动包括：

- 每个 PP stage 捕获自己负责的目标层 hidden states。
- 各 stage 分别计算局部 context projection，并沿 PP 链路累加。
- 最后一个 PP stage 执行 RMSNorm、KV projection，然后生成 DSpark draft KV。
- Prefill 节点向 Decode 节点传输：
  - 各 PP stage 的 target KV
  - 最后一个 PP stage 生成的 draft KV
- 修复不同 PP stage 完成 KV 传输时间不一致造成的调度失步和提前释放 KV。
- 修复 PD 传输时可选状态组件布局不同的问题，改为按状态类型匹配，而不是按数组位置匹配。
- 针对 DeepSeek-V4 的 block-FP8 权重增加按列切分优化，避免重复执行补零后的完整 GEMM。
- 非 DSpark owner 的 PP rank 使用轻量 skeleton model，不加载无用 draft 权重。

支持范围：

- 支持：`PP + DSPARK + PD Prefill`
- 不支持：`PP + DSPARK Decode`
- 不支持：`PP + DSPARK Unified Serving`
- 不支持：`DSPARK + Context Parallelism`

简单说，它主要面向多机或多卡的大规模 PD 分离部署。我们当前单机 TP=4、非 PD 的 DSPARK smoke，并不依赖这个 PR；只有要做 PP 化的 PD Prefill 时才需要它。
